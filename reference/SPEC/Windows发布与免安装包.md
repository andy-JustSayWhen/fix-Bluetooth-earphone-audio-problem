# Windows 发布与免安装包

## 范围

本文规定蓝牙音频设备模式检查器 Windows 正式版本的压缩包结构、启动方式、构建步骤和发布验收。项目采用 FCMA，架构详细内容只以项目根目录 [`Architecture.md`](../../Architecture.md) 为准。

## 用户交付形式

- GitHub Release（GitHub 上可下载的正式版本）必须提供一个 Windows x64 压缩包。
- 用户解压后，压缩包根目录必须直接出现 `一键运行.cmd`，不得要求用户进入子目录寻找入口。
- 用户双击 `一键运行.cmd` 后，应用必须使用压缩包内置运行环境启动，并自动打开本机网页。
- 用户不得被要求预先安装 Node.js、运行依赖安装命令或修改系统环境变量。
- 启动窗口必须提供清楚且不会因 Windows 命令行编码而损坏的提示。启动失败时保留窗口，让用户能看到错误原因；正常运行时关闭窗口即可停止应用。
- 端口被占用时，正式包必须优先提示用户关闭此前启动的工具窗口；如提供更换端口的方法，只能使用当前平台和当前发布包真实存在的入口，不得向 Windows 用户显示 macOS 启动脚本名称。

## 压缩包结构

```text
蓝牙音频设备模式检查器-windows-x64-v<版本>/
├── 一键运行.cmd
├── 使用说明.txt
├── app/
├── core/
├── features/
├── shared/
├── package.json
└── runtime/
    ├── node.exe
    ├── LICENSE-node.txt
    └── README-node.md
```

源码目录只包含应用运行必需文件，不包含测试文件、日志、构建缓存或本机环境文件。运行日志写入解压目录的 `logs/`。

## 内置运行环境

- Windows x64 包固定使用 Node.js 24 的当前长期支持版本。
- 运行环境必须来自 Node.js 官方 Windows x64 压缩包，并保留其许可证和说明文件。
- `一键运行.cmd` 必须通过自身所在目录定位 `runtime/node.exe`，不得优先调用目标电脑环境变量中的同名程序。

## 构建与版本

- 首个正式版本使用 `v1.0.0`，后续版本遵循 `v主版本.次版本.修订版本`。
- 构建产物放入项目根目录 `artifacts/releases/`；临时展开目录放入 `.build/releases/`，两者都不提交版本库。
- 可重复执行的构建脚本放在工具的 `app/` 内，并支持显式传入版本号和 Node.js 版本号。
- 压缩包名称必须包含应用名、平台、处理器架构和版本号。

## 发布验收

发版前必须完成：

1. 运行全部自动测试。
2. 在一个不依赖系统 Node.js 的解压目录中双击等价执行 `一键运行.cmd`。
3. 确认本地端口开始监听，首页和 `/api/devices` 均能访问。
4. 确认页面的“刷新设备列表”能完成刷新，并记录耗时；不得因发版改造明显变慢。
5. 确认关闭启动进程后端口释放。
6. 核对压缩包根目录结构、文件数量和压缩包大小。
7. 提交并推送源码，创建与版本号一致的 Git 标签和 GitHub Release，再上传唯一正式压缩包。

## 不做的事情

- 不制作需要管理员权限的安装程序。
- 不写入注册表、不创建开机启动项、不安装系统服务。
- 不把日志、设备名称、进程列表或本机检测结果放入发布包。

## v1.0.0 实现与验收记录

- 正式包名称：`蓝牙音频设备模式检查器-windows-x64-v1.0.0.zip`。
- 内置 Node.js `v24.21.0` Windows x64 运行环境，文件来自官方下载地址。
- 压缩包大小为 `36,209,774` 字节，共 `65` 个文件。
- 从最终压缩包重新解压后，根目录包含 `一键运行.cmd`、`使用说明.txt`、应用模块和 `runtime/`。
- 在全新解压目录中通过 `一键运行.cmd --port 4199 --no-open` 启动成功，监听进程明确来自包内 `runtime/node.exe`；首页返回 `200`，识别到 `1` 台蓝牙音频设备，设备接口响应约 `15.51` 毫秒。
- 发布包页面“刷新设备列表”实测约 `0.98` 秒完成并更新时间，浏览器警告与错误为 `0`；关闭启动进程后测试端口正常释放。
- 自动测试共 `191` 项：`187` 项通过、`4` 项按运行环境跳过、`0` 项失败。

## v1.0.0 发布后勘误

- 已发现应用入口沿用了最初 macOS 版本的端口占用提示，向 Windows 用户显示了 `./run.command`。该提示不影响已经成功启动的正常流程，但无法指导 Windows 正式包用户处理端口冲突。
- 源码修正为与平台无关的直白说明：先关闭此前启动的检查器窗口；需要更换端口时，在当前启动命令后追加 `--port 4174`。对应 Windows 启动测试必须确认输出不再包含 `run.command`。
