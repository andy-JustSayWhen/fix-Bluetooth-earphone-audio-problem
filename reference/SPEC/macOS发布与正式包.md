# macOS 发布与正式包

## 目标

从 `main` 分支的 macOS 原生实现生成正式压缩包。普通用户完整解压后，双击根目录的 `一键运行.command` 即可使用，不需要另行安装 Node.js，也不需要运行依赖安装命令。

本项目采用 FCMA（按用户功能组织代码的模块化应用架构），详细内容见项目根目录 `Architecture.md`。本规格只约束应用启动与发布交付，不改变声音检测、模式判定或一键修复规则。

## 版本与分支

- macOS 正式版的标签使用 `macos-v<版本>`，标签提交必须属于 `main` 分支。
- macOS 版本与 Windows 版本分别维护，不允许从 `windows` 分支构建 macOS 正式包。
- 首个正式版为 `macos-v1.0.0`。

## 包名与目录

发布文件名称为 `bluetooth-audio-mode-checker-macos-universal-v<版本>.zip`，解压后的根目录为：

```text
蓝牙音频设备模式检查器-macos-universal-v<版本>/
├── 一键运行.command
├── 使用说明.txt
├── app/
├── core/
├── features/
├── shared/
├── package.json
├── .build/                         # 已预编译的通用本机声音组件
└── runtime/
    ├── arm64/node                 # 苹果芯片运行环境
    ├── x64/node                   # 英特尔芯片运行环境
    ├── LICENSE-node.txt
    └── README-node.md
```

## 启动与依赖

- `一键运行.command` 必须保留可执行权限，使用 UTF-8 无字节顺序标记和 Unix 换行。
- 启动器根据处理器自动选择包内运行环境；不支持的处理器必须显示中文错误。
- 正式包必须预编译所有与系统声音交互的本机组件，因此用户不需要安装 Node.js、苹果命令行编译工具或其他开发依赖。
- 默认端口被占用时，应用必须自动选择空闲端口，并用实际端口打开浏览器和校验本机写请求。
- 构建与发布过程不生成、不附带、不发布校验和、哈希清单或其他数字指纹文件。

## 构建与验收

- `app/build-macos-release.sh` 只允许在 macOS 上构建，使用系统编译器生成同时支持苹果芯片和英特尔芯片的本机组件。
- 发布包排除测试文件、构建模板和源码启动脚本。
- 云端验收必须从最终压缩包重新解压并执行根目录入口，而不是直接运行源码。
- 验收必须确认首页和设备接口可访问，并实际占用默认端口以确认自动切换到空闲端口。
- 构建后运行完整自动测试；发布层不得改动刷新设备或切换设备的实现，测试耗时不得出现发布改动导致的回退。
