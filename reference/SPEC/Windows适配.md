# Windows 适配规格与设计

本项目采用的架构以 [Architecture.md](../../Architecture.md) 为原文。Windows 与 macOS 共用网页、功能模块和请求协议，按系统选择底层实现。

## 用户行为

1. Windows 用户双击工具目录 `run.cmd` 启动，要求本机安装支持直接执行类型脚本的 Node.js（运行本工具的基础环境）24 或更高版本。服务仅监听本机。
2. 扫描当前可用输入输出，按真实蓝牙地址聚合蓝牙设备；非蓝牙端点独立保留，不能把同型号的两台设备合并。名称重复时附带稳定端点标识，确保选择唯一。
3. 常驻读取默认角色、混音格式和应用会话。默认设备、连接集合、会话变化自动刷新；完整扫描异步执行，失败向页面显示原因，不能无限显示加载中。常驻进程通过系统设备树接口读取物理归属，无需启动新的系统脚本。
4. 默认输入输出切换使用精确端点标识，依次设置系统三个默认角色并读回确认。接口等待异步操作完成，期间页面请求仍可响应。
5. 输入及输出占用来自对应端点的活动声音会话，列出系统可归属的进程。系统或跨进程会话无法归属时明确保留证据边界。默认麦克风不等于正在录音。
6. 解除占用先再次核实目标端点会话与进程启动时间，只请求用户程序正常退出。无窗口程序或拒绝退出程序报告仍占用；不强杀系统进程。
7. Windows 恢复顺序：重新取证、解除目标麦克风占用、输入输出经非蓝牙端点中转并恢复、必要时重启目标蓝牙设备节点、连续三次确认恢复。没有候选或权限不足时明确记录。目标节点重建可能需要以管理员身份启动工具，不自动重启全机声音服务或蓝牙适配器。
8. 目标节点重建必须绑定唯一蓝牙物理实例，使用系统设备重启命令，等待目标声音端点重新可用。命令完成仅表示执行成功；端点重现与模式恢复分别验收。

## 模式证据

Windows 混音格式是声音引擎内部处理格式，不是蓝牙无线传输采样率，不填入实际传输采样率或硬件可用采样率范围。已有采样率规则仅适用于可读取其所需事实的平台。

传统蓝牙的活动输入会话或活动独立免提输出端点可以支持通话模式判断。只有高混音采样率、默认输出或无麦克风会话时，不足以排除通信类别输出，结果为无法确认。当驱动提供独立立体声与免提输出端点，且只有立体声端点存在活动输出、全部会话可读取、输入和免提输出均无活动会话时，可以确认独立立体声播放。低功耗蓝牙设备独立标记，不套用传统蓝牙通话规则。缺乏可证明高音质恢复的证据时，不报告完全恢复。

依据：[微软传统蓝牙声音说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/bluetooth/bluetooth-classic-audio)、[微软混音格式说明](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getmixformat)。

## 技术设计

- `core/windows-audio-probe/` 通过本机系统声音接口读取端点、默认角色及活动会话；长驻辅助进程持续输出快照，每 750 毫秒重新枚举端点、会话与系统设备树事实；应用合并未变化的结果，每 3 秒补充读取以检测辅助进程失败。子进程关闭、超时、无效输出均明确失败并允许重试。
- `core/windows-audio-control/` 封装默认端点设置、目标设备节点重启与用户进程正常退出；参数按数据传递，禁止拼接设备名称为可执行命令。
- 原有设备判定、麦克风占用、扬声器占用及恢复功能模块接入 Windows 能力，macOS 路径保留。
- 批处理入口仅使用基础英文字符；系统脚本显式使用统一字符编码，中文名称必须完整往返。

## 验收

覆盖物理设备分组、混音格式误判、独立免提端点、默认角色、低功耗设备、失败与超时、进程身份复核及恢复判定测试。执行既有测试以检查 macOS 共用逻辑。实机核验扫描、页面、自动刷新和切换耗时；真实通话恢复只有在本机存在相应现场并完成操作后才能记录为通过。

## 实现边界

- 默认端点设置通过本机声音策略组件执行，其接口不是微软公开承诺长期稳定的应用接口；每次操作必须读回全部默认角色，失败时恢复原角色并报告恢复失败。
- Windows 的连接操作在按钮上显示为重建设备连接；它重启目标物理设备节点并确认声音输出端点可用，不把它描述为已证明无线链路完成断开与重连。
- 输入输出会话属于音频引擎当前报告的活动，不保证系统或跨进程会话能够归属到一个应用；这时显示占用归属无法确认。
- 同时只执行一个 Windows 声音写操作，读取请求不等待写操作。恢复原默认角色失败时不得报告完全恢复。

## 物理设备归属

蓝牙输入输出首先通过系统的 ContainerId（把同一台设备的不同功能归在一起的编号）关联；有效蓝牙地址作为物理身份依据。读取端点自身的容器编号，并在蓝牙设备枚举中查找同容器的远端物理设备节点，不能假设该节点必然是音频端点的祖先。未找到地址时允许以有效容器编号归组，不能按同名强行合并；空编号与系统共享容器编号不能用于合并。蓝牙麦克风启用或停用时，只改变同一卡片中的输入能力。模式仍按本文的独立证据规则判定。

依据：[微软设备容器说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/devpkey-device-containerid)。


Windows 会话读取成功但无声音活动时，页面使用中性色提示未检测到音频活动；有播放但协议证据不足时提示模式待确认。读取失败仍保留错误提示。此展示规则由现有设备判定功能模块负责，不改变协议判定结果。
