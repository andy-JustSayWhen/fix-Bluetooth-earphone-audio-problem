# Windows 适配规格与设计

本项目采用的架构以 [Architecture.md](../../Architecture.md) 为原文。Windows 与 macOS 共用网页、功能模块和请求协议，按系统选择底层实现。

## 用户行为

Windows 扬声器会话按蓝牙地址归属设备，双方地址均通过公共地址规范化函数处理后比较，兼容冒号、连字符及大小写。活动播放会话须显示进程，停止后清除。

Windows 状态变化在对应区域实时更新：模式位于设备名称下方，声音链路位于参数框标题，输入输出的被占用情况与程序名位于参数框内的输入输出区，录音进程及其解除操作位于麦克风占用区，播放进程位于扬声器占用区。每项状态仅在所属区域展示；诊断时序保存在详细日志及实测记录中。

1. Windows 用户双击工具目录 `run.cmd` 启动，要求本机安装支持直接执行类型脚本的 Node.js（运行本工具的基础环境）24 或更高版本。服务仅监听本机。工具按系统目录绝对路径定位 Windows PowerShell，不要求本机 PATH（系统查找程序的环境变量）包含 WindowsPowerShell 目录；PATH 被精简、改写或缺失该目录的电脑上功能不受影响，这是多设备通用的硬性要求。
2. 扫描当前可用输入输出，按真实蓝牙地址聚合蓝牙设备；非蓝牙端点独立保留，不能把同型号的两台设备合并。名称重复时附带稳定端点标识，确保选择唯一。
3. 常驻读取默认角色、混音格式和应用会话。默认设备、连接集合、会话变化自动刷新；完整扫描异步执行，失败向页面显示原因，不能无限显示加载中。常驻进程通过系统设备树接口读取物理归属，无需启动新的系统脚本。
4. 默认输入输出切换使用精确端点标识，依次设置系统三个默认角色并读回确认。接口等待异步操作完成，期间页面请求仍可响应。
5. 输入及输出占用来自对应端点的活动声音会话，列出系统可归属的进程。已关联具体非蓝牙输入端点的活动必须显示该端点名称，不得因其不属于蓝牙设备而写成“未确认麦克风占用”；系统或跨进程会话无法归属时明确保留证据边界。默认麦克风不等于正在录音。
6. 解除占用先再次核实目标端点会话与进程启动时间，只请求用户程序正常退出。无窗口程序或拒绝退出程序报告仍占用；不强杀系统进程。
7. Windows 恢复顺序：重新取证、解除目标麦克风占用、输入输出经非蓝牙端点中转并恢复、必要时重启目标蓝牙设备节点、连续三次确认恢复。没有候选或权限不足时明确记录。目标节点重建可能需要以管理员身份启动工具，不自动重启全机声音服务或蓝牙适配器。
8. 目标节点重建必须绑定唯一蓝牙物理实例，使用系统设备重启命令，等待目标声音端点重新可用。命令完成仅表示执行成功；端点重现与模式恢复分别验收。

## 环境信息操作

Windows 环境配置位于 `.codex/environments/environment-2.toml`；在环境信息的“更改环境”中选择 Windows。提供“重启服务”和“关闭服务”两个 Windows 专用操作，平台字段为 `win32`；原有 macOS 命令使用 `darwin`，其他环境操作保持原配置。

关闭操作查找本机 4173 端口的监听进程，并复核其为本工具入口进程后结束；未运行时正常返回，端口被其他程序占用时报告错误。重启操作先执行同样的关闭逻辑，再从项目根目录进入工具目录启动服务，保持在操作终端中运行。所有路径均相对项目根目录。

Codex 在 Windows 上通过 CMD 执行环境操作，环境配置不得直接内嵌 PowerShell 语句。两个操作必须使用系统目录下 Windows PowerShell 的绝对路径启动 `app/windows-service-action.ps1`，不依赖 PATH；环境命令本身保持为单行 CMD 命令。脚本统一承担端口所有者复核、停止等待和服务启动，避免两个环境操作复制并逐渐分叉。环境动作必须分别完成“关闭后端口不再监听”和“重启后页面接口可访问”的实际验收，不能只根据命令退出状态判定成功。

## 模式证据

模式规则唯一原文为 [如何判定蓝牙音频设备的音频模式](如何判定蓝牙音频设备的音频模式.md#判定顺序)。Windows 与 macOS 使用同一判定函数；平台差异由采集层映射事实，不另设以会话活动代替设备模式的判定规则。

Windows 混音格式是声音引擎内部处理格式，不是原文要求的输出端点运行时钟或无线传输采样率。采集结果可以展示混音值，但必须单独标注来源，不把混音值送入判定用的标称、实际采样率及硬件可用范围。仅有输入活动或独立端点名称时不填充声音链路类型。低功耗蓝牙设备独立标记，不套用传统蓝牙通话规则。

已经独立采集并按设备归属的链路事件，必须进入共同判定函数；经验证具有原文语义的输出可用范围、标称及实际采样率必须保留，不能因存在 Windows 元数据被清空。设备输入活动只更新占用事实。macOS 专属端点快照不能覆盖 Windows 的设备与路由状态。

Windows 完整验收必须分别完成原文两条 HFP 判定路径的实机取证，且复核高音质恢复；规则测试通过不能替代采集能力验收。设备级实时语音链路与高音质流监听均已接入共同规则：语音链路事件完成本机 HFP 页面识别验证；高音质流事件字段已经本机重连记录验证，实时页面验收仍待完成。端点实际运行时钟仍未取得，采样率判定路径保持缺失；未取得的数据保持缺失。

依据：[微软传统蓝牙声音说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/bluetooth/bluetooth-classic-audio)、[微软混音格式说明](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getmixformat)。

## 技术设计

### Windows 参数读取

Windows 端点框展示蓝牙协商格式与实时活动，而非格式查询数值。输出区布局固定为左右两半：左侧“蓝牙协商格式”卡片竖跨右侧两卡的高度，卡内每行一个字段，行首为字段名——依次为“格　式”“编　码”“采样率”“声道数”（“格　式”“编　码”以全角空格补齐三字宽度）；右侧上下两张卡片为“被占用情况”和“播放程序”。输入框显示“被占用情况”和“使用程序”。格式行取值只有两种：高音质播放、低音质通话。语音链路活跃时显示“低音质通话”，不得堆砌已停止的高音质协商记录误导用户；此时编码、采样率、声道数按 Air Mode 经 HFP 标准映射显示（µ-law/A-law、CVSD 为 8 kHz 单声道，mSBC 为 16 kHz 单声道），未取得 Air Mode 时显示“尚未取得”；存在高音质协商时显示“高音质播放”，流停止时加注“（未在传输）”；尚无任何协商证据时显示“尚未取得”，参数行同样显示“尚未取得”。格式行不重复标注协商参数缺失——编码、采样率、声道数行的“尚未取得”已经表达该事实；API 证据与解释文本（页面不渲染）中的“传输中（协商参数尚未取得）”表述保留。被占用情况取值：有会话证据或占用进程时显示“正在被占用”，无活动时显示“未被占用”；输入区需加“此设备”限定，分别显示“此设备正在被占用”和“此设备未被占用”，避免被理解为全机结论；采集状态未知时显示“尚未取得”；程序为空时显示“未识别到”。模式胶囊与声音链路标题继续展示独立连接证据。以下格式查询仅作为内部诊断数据，不在 Windows 设备卡片展示，macOS 参数展示遵守共同规格。占用语义只描述该端点当前有无声音会话；“谁在占用”与解除操作仍以麦克风占用区、扬声器占用区的归属证据为准，两者不得互相冒充。设备卡片之外的其他输入活动若已关联具体非蓝牙端点，必须显示端点名称和“正在占用其他输入设备”，只有无法关联具体实体端点时才显示“具体麦克风未确认”。


- 系统设置格式通过 `PKEY_AudioEngine_DeviceFormat`（系统为设备选择的音频格式属性）读取，独立于混音格式；两者不能回退互填。
- 对输入和输出分别调用 `IAudioClient.IsFormatSupported`（询问设备能否接受指定音频格式的接口）的独占模式查询，检查常见采样率及整数、浮点格式，只记录准确支持的结果。此操作只查询，不初始化录音或播放，不抢占设备。
- 格式支持查询结果是已测试集合，不声称穷尽设备能力，也不能据此认定设备不支持高音质；判定用的完整可用范围仍须有完整来源。
- 驱动运行参数通过只读设备拓扑和音频引擎属性查询验证可行性。尚未取得运行时钟时，实际采样率保留缺失，不能用设置格式或混音格式代替。
- 可用格式结果按端点及设置格式缓存，设备消失或格式变化时失效，定期重查，避免每次页面刷新重复查询；设置格式随每轮快照读取。
- 属性读取失败与没有支持的测试格式分别保留状态。页面不把尚无系统数据、读取失败和未测试混成同一种错误。

依据：[微软设备设置格式说明](https://learn.microsoft.com/en-us/windows/win32/coreaudio/pkey-audioengine-deviceformat)、[微软格式支持查询说明](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-isformatsupported)。

- `core/windows-audio-probe/` 通过本机系统声音接口读取端点、默认角色及活动会话；长驻辅助进程持续输出快照，每 750 毫秒重新枚举端点、会话与系统设备树事实；应用合并未变化的结果，每 3 秒补充读取以检测辅助进程失败。子进程关闭、超时、无效输出均明确失败并允许重试。
- `core/windows-audio-control/` 封装默认端点设置、目标设备节点重启与用户进程正常退出；参数按数据传递，禁止拼接设备名称为可执行命令。
- `shared/windows-powershell/` 统一解析 Windows PowerShell 可执行文件路径：Windows 下按 `SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe` 绝对路径定位并校验存在，文件不存在时回退按名称查找；非 Windows 平台返回名称占位。`core/windows-audio-probe/` 与 `core/windows-audio-control/` 的全部 PowerShell 调用统一使用该入口，不得在模块内散落裸命令名，也不得各自重复实现路径拼接。
- 原有设备判定、麦克风占用、扬声器占用及恢复功能模块接入 Windows 能力，macOS 路径保留。
- 一键修复通过应用组合层传入的模式读取函数获取目标最新判定，并调用既有修复资格函数；每次重新取证后再次读取共同模式结果，不在恢复执行器内部按会话活动推断模式或恢复成功。
- 批处理入口仅使用基础英文字符；系统脚本显式使用统一字符编码，中文名称必须完整往返。

### 运行参数只读取证

诊断入口分别记录声音端点和其连接的驱动设备是否接受内核属性查询；枚举驱动节点类型、音频引擎设置、采样率属性支持情况及实际返回值，并检查端口的当前实例数。每次失败保留原始错误码，不把失败解释为整个系统或耳机不提供。蓝牙和声音事件采集作为另一条取证路径，只有能绑定目标设备且含明确链路事实的结果才能进入模式判定。查询不创建声音流，不更改格式，不开启麦克风。未完成语义验证的数值仅记录在诊断中。

### 实时语音链路采集

常驻探测进程启动独立的本机蓝牙事件会话，实时消费控制器事件；按同步连接成功事件中的蓝牙地址及连接编号维护活动语音链路，并读取事件末尾的 Air Mode（空中模式字节）作为通话编码类别证据。收到对应断开事件、跟踪失败或事件丢失时清除证据。仅成功的同步语音连接映射到共同规则的语音链路事实，普通连接不能用于确认高音质。新会话不从历史记录推断当前连接，开启前已经存在的链路等待下一次实际切换。采集不主动开关麦克风或重连耳机；默认每秒刷新事件缓冲，与声音快照一起返回。缺少权限时保留未知，退出时停止本进程创建的事件会话。

控制器事件确认链路类型并携带 Air Mode：0x00/0x01 对应 µ-law/A-law，0x02 对应 CVSD，0x03 对应透明传输。通话参数按 HFP（蓝牙免提通话协议）标准映射展示——µ-law/A-law、CVSD 为 8 kHz 单声道，透明传输在 HFP 语音中唯一对应 mSBC、即 16 kHz 单声道；来源标注为“通话事件＋标准映射”，不冒充端点实际运行时钟，也不得倒填 A2DP 协商参数或系统设置格式。

进程树被系统强制结束时无法执行退出清理。下次监听启动时，仅清理本工具命名前缀且所属进程已经不存在的遗留会话，保留仍存活实例的会话。

当前原生实时事件读取支持 64 位进程；其他进程位数或权限不足时不产生链路证据。

### 高音质流实时采集

常驻探测进程的同一蓝牙事件会话同时启用高音质流驱动提供程序（BthA2dp，Windows 高音质传输驱动层的事件来源）。按事件字段区分三类事实，并按蓝牙地址维护：

- 配置协商事件（高音质流建立前双方确认参数的信令）结果码为 0 时，记录该地址最近协商的编码编号、厂商编号、采样率与声道数。协商值来自无线链路配置，是当前实际传输参数的直接来源；失败结果不记录。
- 流开始事件把地址标记为高音质流正在传输；带持续时长的流结束事件清除“正在传输”，最近协商参数保留用于展示，不得继续当作当前模式证据。
- 连接状态、引脚创建等其他事件不参与状态机。

跟踪失败或事件丢失时，语音链路与高音质流证据一并清除。协商参数标注来源与时间，不冒充端点实际运行时钟。事件字段结构以本机 2026-09-14 重连记录（artifacts/bose-negotiation-20260914-114148-A2dp）验证：AAC（一种蓝牙高音质编码）协商为 48 kHz、2 声道，随后流开始；通话建立时流停止，通话断开后流重新开始。logman（Windows 自带的事件跟踪会话管理命令）单条命令只接受一个提供程序参数，第二提供程序必须用 update 命令加入同一会话；创建失败时进程保持无证据状态，不得回退为只读其一。

实时事件会话同时写入循环历史文件（工具 logs 目录，约 16 MB 循环覆盖），实现共同规格要求的启动历史补读：进程启动时先回放上一轮历史文件，最近 30 分钟内的事件作为该设备当前链路状态初始值；超过 30 分钟的事件不再充当"正在传输"，只保留协商参数供展示。服务停机期间无人监听，那段时间发生的状态变化无法补读，由下一次实时事件修正。回放后删除旧文件并建立新会话，历史文件不随代码提交。

## 物理设备归属

蓝牙输入输出首先通过系统的 ContainerId（把同一台设备的不同功能归在一起的编号）关联；有效蓝牙地址作为物理身份依据。读取端点自身的容器编号，并在蓝牙设备枚举中查找同容器的远端物理设备节点，不能假设该节点必然是音频端点的祖先。未找到地址时允许以有效容器编号归组，不能按同名强行合并；空编号与系统共享容器编号不能用于合并。蓝牙麦克风启用或停用时，只改变同一卡片中的输入能力。模式仍按本文的独立证据规则判定。

依据：[微软设备容器说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/devpkey-device-containerid)。


模式胶囊遵守模式规则原文的固定文案；占用活动在占用区域展示。输入、输出框按本文“Windows 参数读取”的实时活动要求展示。

## 验收

覆盖物理设备分组、混音格式误判、独立免提端点、默认角色、低功耗设备、失败与超时、进程身份复核及恢复判定测试。执行既有测试以检查 macOS 共用逻辑。实机核验扫描、页面、自动刷新和切换耗时；真实通话恢复只有在本机存在相应现场并完成操作后才能记录为通过。

## 实现边界

- 默认端点设置通过本机声音策略组件执行，其接口不是微软公开承诺长期稳定的应用接口；每次操作必须读回全部默认角色，失败时恢复原角色并报告恢复失败。
- 输入输出会话属于音频引擎当前报告的活动，不保证系统或跨进程会话能够归属到一个应用；这时显示占用归属无法确认。
- 同时只执行一个 Windows 声音写操作，读取请求不等待写操作。恢复原默认角色失败时不得报告完全恢复。

### 设备声明能力的采集路径

Windows 设备支持能力取自设备的蓝牙能力响应或可验证的服务声明，不使用应用侧候选格式查询代替。已连接设备优先进行下文的主动服务查询。A2DP（含义见共同模式规格）按设备地址关联普通连接编号，再关联声音信令通道及请求事务编号；解析 GetAllCapabilities（获取端点完整能力的协议请求）成功响应中的媒体编码能力。保留各远端声音端点及编码对应的采样率集合、声道模式和原始响应，不能只保存最高值或把不同编码的组合任意拼接。能力与当前选定配置分开存储；有能力不代表当前正在传输。
